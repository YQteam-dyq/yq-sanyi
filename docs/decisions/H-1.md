# H-1 语法形态决策文档

## 决策背景

在 yq-sanyi Phase 2 中，需要确定组件定义的语法形态。本对比评估两种方案：

- **Form-A**: 注册式三段语法 `yq.define(name, {template, style, script})`
- **Form-B**: 模板就近组织语法 `<template data-yq="name">` + 内嵌三段

## 对比维度

| 维度 | Form-A 注册式三段 | Form-B 模板就近组织 | 评分说明 |
|------|------------------|-------------------|----------|
| **file:// 可用性** | ⭐⭐⭐⭐⭐<br>无构建依赖，直接打开 | ⭐⭐⭐⭐⭐<br>无构建依赖，直接打开 | 两种方案均支持文件直接打开，无需构建工具 |
| **预扫描模式** | ⭐⭐⭐⭐⭐<br>显式注册，按需解析 | ⭐⭐⭐<br>全文档扫描，查找所有 data-yq | Form-A 只解析已注册组件，Form-B 需扫描整个文档 |
| **Web 标准贴近度** | ⭐⭐⭐<br>自定义 API，非标准 HTML | ⭐⭐⭐⭐<br>使用标准 template 标签，扩展语义 | Form-B 更贴近 Web 标准，使用原生 template 元素 |
| **可测试性** | ⭐⭐⭐⭐⭐<br>集中管理，易于单元测试 | ⭐⭐⭐<br>分散定义，测试需 DOM 环境 | Form-A 组件定义集中，便于独立测试；Form-B 依赖 DOM |
| **首屏解析成本** | ⭐⭐⭐⭐⭐<br>只解析使用到的组件 | ⭐⭐<br>扫描整个文档查找组件 | Form-A 解析成本更低，按需加载；Form-B 需预扫描全文 |
| **作者心智负担** | ⭐⭐⭐⭐<br>API 一致性，明确分离 | ⭐⭐⭐<br>就近原则，但需理解 data-yq 语义 | Form-A API 统一，学习成本低；Form-B 更直观但需新概念 |

## 决策结论

### 主案选择：Form-A 注册式三段语法

**选择理由：**

1. **性能优势**：首屏解析成本更低，只解析实际使用的组件
2. **可维护性**：组件定义集中，便于大型项目的统一管理和维护
3. **开发体验**：API 一致性高，学习成本低，符合模块化开发习惯
4. **测试友好**：组件定义独立，无需 DOM 环境即可进行单元测试
5. **明确分离**：三段职责清晰，便于工具链集成和自动化处理

### Form-B 作为可选模式

**适用场景：**
- 小型项目或快速原型开发
- 组件与使用位置强相关的场景
- 偏好 HTML 模板文件内联定义的开发者

**限制：**
- 需要全文档扫描，性能开销较大
- 依赖 DOM 环境，测试复杂度增加
- 组件定义分散，大型项目维护困难

### 实施建议

1. **核心 API**：采用 Form-A 的注册式三段语法作为主要 API
2. **工具链支持**：基于 Form-A 开发开发工具、IDE 插件等
3. **文档示例**：主要使用 Form-A 语法，Form-B 作为补充说明
4. **渐进式采用**：允许两种语法并存，但推荐使用 Form-A
