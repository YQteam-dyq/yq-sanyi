# H-5 脚本执行方式决策文档

## 决策背景

在 yq-sanyi Phase 2 中，需要确定组件脚本段的执行方式。本实验评估两种方案在严格 CSP（Content Security Policy）环境下的可用性：

- **函数式**：`script` 参数为普通 JS 函数，直接引用执行
- **字符串式**：`script` 参数为字符串，通过 `new Function` 惰性编译执行

## 引擎级事实

### Node.js 环境

1. **函数式执行**：完全支持，无需任何特殊权限
   ```javascript
   const script = function() { return { message: '成功' }; };
   const factory = () => script;
   const result = factory(); // 正常执行
   ```

2. **字符串式执行**：`new Function` 在 Node.js 中可用
   ```javascript
   const script = 'return { message: "成功" };';
   const factory = () => new Function('return ' + script)();
   const result = factory(); // 正常执行
   ```

3. **直接 new Function**：Node.js 环境完全支持
   ```javascript
   const result = new Function('return "成功";')(); // 正常执行
   ```

### CSP 规范依据

根据 CSP3 (Content Security Policy Level 3) §6.6.2：

> The `unsafe-eval` source expression specifies that the usage of `eval()` and functions equivalent to `eval()` are permitted.

**关键影响**：
- 当 CSP 策略为 `script-src 'self'`（不含 `unsafe-eval`）时：
  - `eval()` 被禁止
  - `Function()` 构造函数被禁止（被视为 `eval` 等价物）
  - `setTimeout(..., string)` 等动态执行 API 被禁止

**实际影响**：
- 函数式组件：不受 CSP 限制，可直接执行
- 字符串式组件：首次调用 `new Function` 时抛出 `EvalError`

## 决策结论

### 主路径选择：函数式为一等公民

**选择理由**：

1. **CSP 兼容性**：函数式组件在严格 CSP 环境下完全可用，无需 `unsafe-eval`
2. **安全性**：避免动态代码执行，降低 XSS 风险
3. **开发体验**：类型检查、IDE 支持、调试友好
4. **性能**：无编译开销，直接函数引用
5. **工具链支持**：更易与构建工具、打包器集成

### 字符串式作为降级方案

**适用场景**：
- 动态脚本需求
- 兼容性要求
- 运行时代码生成

**限制**：
- 依赖 `unsafe-eval`，严格 CSP 环境不可用
- 安全风险较高
- 调试困难，类型丢失

### 实施建议

1. **默认推荐**：使用函数式组件
2. **文档指引**：明确字符串式组件的 CSP 限制
3. **错误处理**：提供清晰的 CSP 错误提示
4. **开发工具**：在 devtools 中标记字符串式组件的 CSP 风险

## 技术实现

```typescript
createScriptFactory(function() {
    return { data: 'value' };
})

createScriptFactory('return { data: "value" };')
```

函数式（推荐）传入普通函数，`createScriptFactory` 返回 `() => function() { return { data: 'value' }; }`；字符串式（受限）传入源码字符串，返回 `() => new Function('return { data: "value" };')()`，在无 `unsafe-eval` 的 CSP 环境下调用时抛 `EvalError`。

## 错误处理策略

当字符串式组件在 CSP 环境下失败时：

1. **开发环境**：在控制台显示详细错误和解决方案
2. **生产环境**：优雅降级，提供默认行为
3. **DevTools 集成**：在组件面板显示 CSP 警告

## 决策时效性

本决策基于 CSP3 规范和当前浏览器引擎行为制定。如浏览器 CSP 政策调整，需重新评估。
